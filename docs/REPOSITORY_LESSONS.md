# リポジトリを題材にした解説

調査から制作へ進む前にcontent-production Skillを適用し、「制作ブリーフ」のテーマ・目標時間・視聴者・構成などを確認します。未回答ならユーザーに入力を尋ねます。以下の手順はその制作条件を引き継ぎます。

台本ノートの「台本を開く」にあるリポジトリURL欄から、調査依頼を作りChatGPTへ渡します。現在はChatGPTが調査・台本作成を担当し、エディター内でAIを自動実行する方式ではありません。

## 調査から編集まで

1. 対象をcache/repositories以下に取得し、コミットを固定する。コードはまず静的に読む。対象がアプリ、ライブラリ、記事、調査資料のどれなのか確認する。
2. `python repository_context.py <checkout> --output <新しいcontext.json>` でURL・コミット・追跡ファイル一覧・作業ツリーの変更有無を記録する。cloneやインストールはこのコマンドに含まれない。
3. READMEだけでなく、入口・主要処理・保存・通信・エラー・テストを必要に応じて調べる。存在しない実装や不足した依存ファイルは明記する。記事の分析、コードで確認できた事実、教材独自の説明例を区別する。
4. 利用者の疑問から章を組み立てる。ファイルを順番に読み上げる構成にせず、具体的な操作を起点にデータの流れを追う。
5. `lessons/<題材>/lesson.json` と `SOURCES.md` を作る。台本表記はscript-writing Skillに従う。コード引用を増やすより、短い独自の説明例を使い、実装そのものと混同しないよう表示する。
6. 台本のrepositoryメタデータと場面のsourcesにコミット固定の参照を付ける。エディターの場面に出典リンクが表示される。音声・動画生成を行ったか、コードを実行したかはそれぞれ分けて記録する。
7. 台本を編集用コピーとして読み込み、必要なら自動演出・場面プレビューを使う。既存のユーザー編集を元の教材で上書きしない。

## 出典の形式

```json
{
  "repository": {
    "url": "https://github.com/owner/repo",
    "commit": "40文字のコミットSHA",
    "kind": "静的解析",
    "checkedAt": "2026-09-06"
  },
  "scenes": [{
    "sources": [{
      "path": "src/example.ts",
      "startLine": 10,
      "endLine": 30,
      "note": "処理の入口。説明用コードは別途作成"
    }]
  }]
}
```

初回の題材はwzhudev/reverse-linear-sync-engine。Linearの調査記事と注釈付きブラウザーバンドルであり、独立した同期サーバーの実装・実行可能なアプリ一式とは扱わない。取得した第三者コード・画像はキャッシュ内に保持し、このリポジトリへ転載しない。
