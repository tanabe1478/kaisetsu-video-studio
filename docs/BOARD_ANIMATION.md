# AIが設計する黒板アニメーション

ユーザーは台本の文言・構成・学習目的を伝え、生成された場面動画へフィードバックする。配置、動き、秒数の指示は不要。台本ノートの「AIに渡す」で保存した台本を、この会話のAIが読み、図と動きの設計を含む新しい台本へ改訂する。画面内で外部LLMを自動呼び出しする機能ではない。

## AIの作業

1. 場面の理解目標を1つ定める。何が何に変わるか、どの関係を比較するかを決める。
2. セリフを変えずに、対象が移動・集約・分類される動きや、線を描く過程を設計する。装飾的な動きの連続を避ける。
3. `scene.boardAnimation`を作る。既存の`board`は静的な予備図として残せるが、動画ではアニメーションが優先される。
4. 図が説明より先に答えを出しすぎないよう、セリフ番号とセリフ内の進行率へ動きを結びつける。音声の長さは合成後の実測を使う。
5. 開始・途中・終了のフレームを確認し、場面動画を生成して変化を検証する。ユーザーは分かりにくい箇所だけメモに残せる。

## 形式（AI向け）

`boardAnimation`: `version:1`, `intent`（何を理解させるか）、`narration`（対応する字幕を順番通り保存）、`elements`（最大60要素）。現行の例は`lessons/epiplexity/build_motion_example.py`。

各要素は一意な`id`、`type`、任意の`text`、`color`、`fontSize`、`frames`を持つ。typeは`box`、`text`、`dot`、`arrow`、`path`。arrow/pathは0〜1の相対座標の`points`を持つ。図版・プログラム・外部URLの実行はしない。

各フレームは1始まりの`line`、セリフ内の割合`at`（0〜1）、`x/y/w/h`、`opacity`、`progress`。座標は黒板内部700×280の範囲。省略値はx/y=0、w=100、h=50、opacity/progress=1。フレームは差分ではなく状態を記す。時間順に並べる。最初のフレーム前は非表示、最後の後はその状態を維持する。状態間は滑らかに補間し、path/arrowのprogressで線を順に描く。

セリフの長さが変わっても動きは追従する。セリフ末尾から次のセリフまでの間は最終状態を保持する。表情・字幕は既存の音声タイムラインを使う。話者が1人でも2人でも同じ黒板描画を利用する。

台本ノートの静止画は選択セリフの75%地点。動きを見るには「場面プレビュー」を使う。アニメーション付き場面では手動の項目数・強調入力を隠し、意図とプレビューを表示する。

字幕の変更・並べ替えは保存できるが、古い演出でのプレビュー・動画出力は拒否する。AIが新しい台本を確認して再設計する必要がある。ユーザーが直した文言を、演出に合わせて元へ戻さない。

## 実験グラフ

実測値を示す場合は検証済みデータが必要。説明用に形を描くときは「模式図／実測値ではない」を画面に明示し、数値や面積を測定結果として主張しない。

## 試作

今回の承認済みEpiplexity台本から3場面を抜粋し、反復の圧縮、モデルと残りへの分解、学習曲線の比較をAIが設計した。元の20分版は保持。`build_motion_example.py SOURCE NEW`はこの具体的な絵コンテを再現するためのコードであり、任意の台本をキーワード分類してAI生成と呼ぶものではない。新しい題材はAIが内容を読んで別の設計を作る。
